# Web 前端重构计划

## 目标与范围

提升 `apps/web` 的可读性、复用性和可维护性，以职责清晰、状态来源唯一、行为可验证为目标，不以文件行数或 hook 数量作为成果指标。

- Phase 0–4 为本轮范围：建立基线后进行保持行为不变的内部重构。
- Phase 5 为后续独立改进：另行确认交互、依赖和验收标准，不默认执行。
- 保持现有业务规则、API 语义、节点 ID、文案、布局、草稿保存和历史读取行为。
- 发现既有缺陷时单独记录和修复，不夹带在代码搬迁中。
- 本计划尚未执行，下面的测试与验收要求不代表已完成结果。

## 已核实的现状

- Studio 已使用 React Flow 的 `useNodesState` / `useEdgesState`，并用 callback-ref 桥接节点操作。
- Session 用同一个 `historyRequestRef` 协调模板切换、历史加载和新运行重置，需要共同的请求失效边界。
- 已有 `workflow-action-registry.js`、request-scope、SSE 连接管理及视图模型测试，不另建平行实现。
- 产物展示不只是按节点 ID 匹配，还包含产物类型、数据形状、开始节点特例和通用兜底。
- `styles/README.md` 要求保持 CSS 导入和覆盖顺序；同名工具类不能仅凭名称判定为可删除。
- `npm run test:all` 包含单元、集成、skill 测试与构建，不包含浏览器回归。
- `test/browser/run-regressions.mjs` 当前只运行五个脚本，不能代表所有浏览器专项用例已覆盖。

## 状态归属与不变量

以下是应保持的职责边界，不要求新增对应 store。

| 状态/资源 | 归属 | 不变量 |
| --- | --- | --- |
| nodes / edges | Studio 中现有 React Flow state | 不增加另一份可写镜像，只更新必要节点 |
| 当前运行 ID、状态、日志 | runtime hook | 后端快照和事件是运行事实来源，旧运行不能覆盖新视图 |
| 模板切换、历史载入、新运行重置 | session hook | 共享失效序号、断开订阅及重置流程 |
| 节点选择、侧栏、弹窗 | 当前 UI 所属组件/hook | 不改变初始折叠策略和关闭行为 |
| 产物请求、确认操作 | 原有 request-scope | 同通道防重，切换或卸载后丢弃迟到响应 |
| 铺货任务与轮询 | distribution job hook | 完成后同步运行快照，旧响应不得覆盖完成状态 |
| 表单草稿和自动保存 | 现有表单/草稿 hook | 按运行隔离，保持重开恢复及关窗保存语义 |
| SSE、定时器、回调 ref | 创建它们的 hook | 成对清理，StrictMode 重放和卸载不产生重复订阅 |

## Phase 0：建立验证基线（必须先做）

### Step 0.1 — 盘点依赖与现有行为

- 列出 Studio、session、runtime、operations、overlay、distribution 的调用关系和状态写入点。
- 对照后端整理运行、节点、铺货状态，记录未知值及历史值处理方式。
- 比较 `workflow-data.js` 的活跃状态与 `workflow-node-actions.js` 的可暂停状态，不假定集合等价。
- 记录基线命令、结果、已有警告和环境要求，既有失败不能记为通过。
- 浏览器回归使用本地 API 替身，不启动真实商家采集或真实铺货。

### Step 0.2 — 补齐回归入口与关键用例

复用 `test/unit/web/` 和 `test/browser/`，不在 `src` 散放测试。复用现有视图模型、Session 和 hook 竞态用例，按缺口补充，不另建框架。

检查以下专项脚本的独立运行条件、隔离和清理能力后，纳入统一入口；未纳入时显式逐项执行并记录：

- `distribution-job-refresh.mjs`
- `distribution-copy-formats.mjs`
- `distribution-shops.mjs`
- `unified-selection.mjs`
- `discovery-direction.mjs`

| 场景 | 必须保持的结果 |
| --- | --- |
| A 历史请求未完成时切到 B 或新模板 | A 的响应、报错、事件不覆盖新视图 |
| 模板/模式切换、重复运行 | 草稿正确保留或重置，旧产物不混入新运行 |
| 连点确认、暂停、重试 | 不重复提交，pending 与当前运行对应 |
| 节点动作和产物 | 开始节点无产物；只读、失败、阻塞和恢复动作一致 |
| 铺货核对与完成 | 成功/失败及原因更新，完成后同步完成节点，旧轮询不回写 |
| 复制内容 | 三种格式、成功/失败反馈及复制降级顺序保持一致 |
| 弹窗和草稿 | 重开可恢复，取消不提交，自动保存不串运行 |
| 生命周期 | 卸载、StrictMode 重放、SSE 重连不产生多余订阅或写入 |
| 布局 | 侧栏可收起，日志在底部，长列表可滚动，提示不被遮挡 |

建立桌面、窄屏截图基线，并覆盖现有关键断点两侧。检查画布、节点按钮、产物弹窗、铺货面板、长文本及错误提示，不改变断点值。

**完成条件：** 基线可复现，缺失用例已补充或明确阻塞原因，状态归属和测试清单已记录。

## Phase 1：常量与纯函数整理

### Step 1.1 — 按语义归拢常量

候选模块为 `workflow-statuses.js`、`workflow-node-ids.js`，仅在确有跨模块复用时新增，不为每个字符串建立常量。

- 分开定义运行、节点、铺货状态；活跃、可暂停、可重试、终态使用语义明确的集合或谓词。
- 为已有集合差异补测试；业务含义的统一另行处理，不在替换引用时改变行为。
- 节点 ID 保持后端原值和大小写，保留原边界中的大小写归一化及历史兼容规则。
- 限额放在所属业务模块附近，区分后端约束、业务限制和 UI 展示上限；真正共享时才抽取。
- 调用方直接引用实现模块，不新增 re-export/barrel。

### Step 1.2 — 提取可独立验证的逻辑

- `verifiedRows` 聚合提取为纯选择函数，保持来源优先级和空数组语义，是否 memoize 由调用方决定。
- 提取重复边样式、节点重置等辅助函数，保持返回结构、引用隔离和回调注入行为。
- `copyText` 是带 DOM 副作用的浏览器工具，不是纯函数；保持现有复制顺序、异常传播及 DOM 清理。
- 不为数行逻辑自动新增 hook；新模块必须具有清晰职责、调用方和测试入口。

**验证：** 相关单元测试及构建；涉及复制、状态和按钮时，补跑对应浏览器回归。

## Phase 2：节点展示与动作处理器整理

### Step 2.1 — 先整理产物展示

保持 `getWorkflowArtifactView(artifact, nodeId)` 签名和返回结构，逐个业务分支提取处理器。

顺序保持为：公共特例（含开始节点）→ 空产物处理 → 节点处理器中的类型/数据形状判断 → 原通用兜底。

- 注册表只负责路由，不替代处理器内的业务判断。
- 明确未匹配与匹配到空结果的区别，不能把有效空结果交给下一层兜底。
- 保留未知节点、未知类型、缺字段、空数组、文本及历史数据的展示结果。
- 按业务聚合处理器，不强制每个节点一个文件。

### Step 2.2 — 再整理动作和成功摘要

- 逐个处理 `getWorkflowNodeAction`、`getWorkflowNodeSuccessLabel`，先整理输入归一化和分支优先级。
- 节点状态、配置和只读标志仍参与判断；继续使用现有 action registry，不建立第二套路由。
- 保持标签、动作代码、tone、缺省结果和顺序，一次迁移一个业务组。
- 主要收益是可读性，不是 O(1) 查表；能清晰表达优先级的条件分支可以保留。

**验证：** 数据驱动用例覆盖正常、阻塞、失败、空值及多条件同时命中，迁移前后输出一致；节点按钮和产物浏览器回归通过。

## Phase 3：Studio 与 Session 适度解耦

### Step 3.1 — Studio 按职责收敛

- 保留顶层编排、React Flow state 和必要 callback-ref 桥接，不设行数目标。
- 优先移出 Phase 1 已验证的纯逻辑和浏览器工具。
- 布局形成独立职责时才提取 `use-workflow-layout`；不把首次宽度判断改成每次 resize 重置侧栏。
- 节点更新/动作分发如提取 hook，明确输入、输出及唯一写入点，不能让 hooks 相互回调形成循环依赖。
- 保持铺货完成刷新、产物重开刷新、事件处理和操作防重语义。
- 仅在明确需要稳定引用或缓存计算时使用 `useCallback` / `useMemo`，依赖完整，不要求给所有函数包裹。

### Step 3.2 — Session 保持统一生命周期

- 本轮不拆成三个独立的模板、历史、新运行 hooks。
- `historyRequestRef`、模式草稿、模板初始化保护和订阅清理由原 session 协调。
- 复用节点重置、边样式函数，保留重置顺序及重复运行时使用新节点快照的行为。
- 可注入同步确认函数便于测试，默认仍保留原确认方式；异步弹窗留到 Phase 5。
- 后续确需拆分，先设计共同 session controller 和失效协议，不能复制 ref 或用全局变量替代。

**验证：** Session/hook 竞态、模板切换、重复运行、历史删除、铺货完成同步及 StrictMode；确认没有增加重复请求或订阅。

## Phase 4：API 与样式的等价整理

### Step 4.1 — API 按业务职责拆分

- `workflow-api.js` 可分出评价资料/附件等内聚模块，不为缩短文件机械拆分。
- URL 和请求体构造属于传输协议的 builder 可以留在 API 层，只有业务规则移到领域纯函数。
- 上传助手保留原始 `File` / `Blob` 请求体，禁止 JSON 序列化；保留 Content-Type、X-File-Name、查询参数和编码。
- 保留 `ApiError.status/payload`、接口错误文案、`allowApiError`、产物 404 返回 null 以及响应解包语义。
- 保留调用方 signal、`keepalive` 等选项，本阶段不增加全局超时或自动重试。
- 调用方直接导入实现文件，不通过旧文件 re-export 过渡。

**验证：** fetch 替身检查 URL、method、headers、body、signal、keepalive、错误处理和返回值；涉及路由契约时运行集成测试。

### Step 4.2 — CSS 等值令牌化

- 先盘点重复选择器和覆盖关系，遵守现有 CSS 导入顺序。
- 仅将确定同语义且同值的颜色抽为变量，不合并相近颜色，不调整尺寸、布局或断点。
- 暂不删除 foundation 工具类，不合并按钮系统，不迁移 Tailwind 写法。
- 记录 JS `matchMedia` 和 CSS 断点对应关系；共享方案另行设计，不采用未经构建验证的变量语法替换媒体查询。

**验证：** 构建、桌面/窄屏截图和滚动/遮挡检查；关键计算样式与基线一致。固定动态截图噪声，不能用噪声掩盖布局变化。

## Phase 5：后续独立改进（不属于本轮交付）

| 提案 | 启动条件与约束 |
| --- | --- |
| Zustand 或 Context | 先证明具体跨层共享问题，按领域迁移、唯一可写来源；禁止 store 与 props 双写，不复制 React Flow 状态 |
| toast / dialog | 单独确认交互，区分提示与破坏性确认；设计等待期间运行切换、防重、焦点返回、键盘及取消行为 |
| 请求超时 | 区分只读和有副作用操作；请求超时不等于后台取消，启动/确认铺货后先查询实际状态，不能盲目重试 |
| TypeScript | 先补 JSDoc 和数据契约；采用 TS 时配置实际 typecheck 命令，不仅添加未被消费的 .d.ts |
| 按钮统一、Tailwind | 独立视觉变更，先建立组件状态规范和截图基线，再逐区域替换 |
| 性能优化 | 依据渲染次数、重复请求、订阅数量及包体积等实测定位，不以行数代替性能指标 |

## 验证命令与提交门禁

从仓库根目录执行：

```bash
# 前端纯函数和视图模型
node --test test/unit/web/*.test.mjs

# 静态检查与构建
npm run lint --prefix apps/web
npm run build

# Phase 0 补齐入口；未纳入的专项需单独运行
npm run test:workflow-browser

# 最终集成验收，不包含浏览器测试
npm run test:all
```

- 每步至少运行受影响测试和构建；Session、runtime、公共 HTTP、样式变更须增加相应浏览器或协议回归。
- 每阶段结束运行前端单测和浏览器回归，最终运行完整测试；lint 既有问题记录基线，本轮不新增违规。
- 缺依赖、浏览器或环境时明确报告未验证及原因，不能以构建成功代替行为验收。
- 每个提交只包含一个可回退的重构单元及测试，搬迁、业务修复、视觉变更分开。
- 记录职责变化、删除的重复实现、导入变更和验证结果，检查无新增循环依赖或双状态来源。
- 如需回退，使用独立逆向提交，保留后续工作和用户修改。
- 只有用户要求时才提交或推送，不因计划包含小步提交自行执行远程操作。
