# 项目可读性与简化重构计划

状态：通用工作流与合规选品范围已收尾（2026-09-09）。原计划中的刷单、虚假评价专用功能不继续增强或迁移，不宣称原始全部业务范围完成。
参与：Codex 代码检查与方案整合；Antigravity 基于已提供代码事实进行独立评议。
协作记录：设计阶段 Antigravity 的只读检查曾被权限阻止；实施阶段已通过 agy 完成四个前端规则模块的拆分。Codex 审查并还原了夹带的展示文案变化，随后进行函数结构对比、测试与构建。Antigravity 另对事件与请求竞态给出只读评议，不将评议文字算作测试结果。

## 目标与范围

让开发者能从一个节点按钮追踪到请求、运行状态和产物，减少同一规则在多个位置重复维护。优先处理状态恢复缺陷，再进行保持行为的结构调整。

本轮覆盖 Web 工作流、后端工作流适配器与 HTTP 接口、样式组织和对应测试。CLI、MCP、平台采集器及各 skill 的深层算法保留为后续独立评估项；本轮只验证它们已有入口的兼容性。

收尾范围调整：完成通用连接/状态、选品/铺货、公共 HTTP 基础设施和 CSS 组织；不继续处理刷单、虚假评价专用接口。以下旧设计保留作历史记录，最终验收以末尾收尾记录为准。真实平台登录、风控及实际提交不在离线测试证明范围。

不以文件行数作为验收目标；不新增状态框架、TypeScript 构建或分布式锁；不改变机会评分、限流、平台查询、自动铺货确认及业务表格格式。已有种子池数据变更不属于本轮提交范围。

## 阶段 1：修复状态和连接生命周期

负责人：Codex 实现；Antigravity 针对事件顺序和反例复核。

### 状态合同

- 配置：用户启动参数，只在新建或编辑时改变。
- 运行状态：后端快照为依据，包括 status、progress、blocker、output。
- 临时操作状态：前端持有 pendingAction、operationMessage、连接状态。
- 视图状态：节点选择、弹窗、侧栏和视口继续留在前端。
- 分开实现完整快照替换与增量补丁；补丁字段不存在时保留，存在且为 null、0、false 或空字符串时按字段合同应用。不能机械替换为 `??`。
- 统一新建、复制运行、切换历史和操作完成时的临时字段清理。操作结果使用运行 ID 和请求代次隔离，防止旧请求覆盖新运行。

### SSE 恢复

- 保持单一连接所有者，选择一种重连策略；原生 EventSource 重连与手动重连不能并行存在。
- 短暂断线显示连接恢复状态，连接重建后以服务端快照同步；404、运行删除、卸载或切换历史时停止旧连接。
- 先检查 runtime 事件现有 ID 与版本；优先复用，缺失时才增加可恢复游标。连接代次隔离旧连接，事件游标去重回放，避免用日志文本去重。
- 明确每次连接 init 是当前快照，replay 仅供日志恢复，不回写旧节点状态。终态先同步节点，再关闭连接。
- 重连只恢复读取，绝不自动重发启动、重跑、继续或铺货命令。
- 主动暂停、等待复核与完成是不同状态；分别定义是否继续订阅及用户继续后如何恢复。

验收：模拟断线恢复、重复回放、切换历史、快照与增量交错、冷却归零、解除阻塞、重试失败和复制旧运行；节点不残留旧按钮/提示，日志不重复追加，同一操作不因重连再次执行。

## 协作与提交规则

- 实施时各阶段单独检查与提交；行为修复和纯文件迁移分开，失败时只回退对应提交。
- 同一阶段不让双方编辑同一文件；Antigravity 的修改由 Codex 阅读差异并验证后整合。
- 不把 Antigravity 的文字建议视为测试结果。若工具受限，Codex 可继续实施，报告实际完成者和检查范围。
- P0 -> P1 -> P2 -> P3 -> P4 -> P5 -> P6；可并行收集证据，但共享状态与公共入口的修改顺序保持串行。
- 现有数据不做批量迁移；需要新增事件元数据时兼容旧运行。共享 CJS/ESM 常量前先验证工具链，无必要不增加双格式包。

## 对 Antigravity 建议的取舍

采纳状态生命周期、事件时序、前后端权威边界和 CSS 视觉回归建议。调整四项：null 清空必须用字段存在性判断；优先保持全局单任务互斥而非引入 KeyedMutex；兼容路由按 HTTP 方法注册；先保留 CSS 体系和模块系统。事件版本与命令幂等键仅在现有机制不足且有复现测试时补充，不能把重构扩大为整套协议重写。
