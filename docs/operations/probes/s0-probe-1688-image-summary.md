## 1. 探针目标与选型结论

针对同行截流与图搜选货流水线中的核心技术假设，本轮 S0 探针完成了全面验证：

### 1.1 1688 图搜通道决策
- **OpenAPI 评估**：当前账号与客户端无获授权的开放平台图片检索接口（缺少凭证、权限范围未覆盖）。
- **最终决策**：**选定基于已登录 Chrome 实例的 CDP 网页上传通道**（`https://www.1688.com/` 上传图片 -> `https://air.1688.com/kapp/1688-search/pc-image-search/` 结果页）。
- **刚性门禁**：图搜通道不可用或被风控阻塞时，**严格返回阻塞状态（`manual_action_required`），绝不降级为文字搜索替代**。

### 1.2 淘宝双通道策略
- 支持 `native`（淘宝客户端）与 `web`（Chrome CDP 网页抓取）双通道。
- 运行时固定单次运行通道（`channel pinning`），风控或权限缺失时不静默自动漂移跨通道绕过。

## 2. 四大探针执行结果与数据基线

### 2.1 探针 1：淘宝图搜原始数据店铺信息覆盖（Q1）
- **实测结果**：
  - 网页端（Web 通道）图搜卡片可以直接提取 `shopName`，在现代店铺卡片中包含明确的店铺链接（`shopUrl`）。
  - 部分未提供店铺入口的商品（如部分品牌直投无外显店铺页），系统保留 `shopUrl: null`，不通过店名猜测店铺 ID。
- **决议结论**：
  - **默认使用卡片直接解析的店铺入口进行候选聚合**；
  - 缺失店铺链接的商品暂不投入高成本二次请求，直接跳过，避免因解析单个店铺引发大量并发访问。

### 2.2 探针 2：淘宝商品页价格提取与单件价（Q3）
- **实测结果**：
  - 对淘宝商品（如 `892291403015`）执行详情探测，页面外显价格为区间起步价（如“75元起”），四种规格涵盖不同克重与尺寸。
- **决议结论**：
  - **淘宝列表或详情起步价不能直接认证为已核验单件价**（`singlePiecePriceVerified: false`）；
  - 源商品比价时必须确保其比价基准价明确，否则进入 `inconclusive`，杜绝误用起步价导致利润虚高。

### 2.3 探针 3：1688 搜索结果卡片起订量与价格特征（Q6）
- **实测结果**（基于 60 个真实图搜卡片切片统计）：
  - 60/60 (100%) 成功提取商品 ID（`offerId`）与标题。
  - 60/60 (100%) 成功提取起订量（MOQ）：53 个为 1 件起批（88.3%），7 个为批量起批（2件/5件/10件）。
  - 卡片展示价多包含首单价、新人价、阶梯起步价（如展示价 `¥3`，实际详情规格标价为 `¥28~¥45`）。
- **决议结论**：
  - **卡片展示价仅作为粗筛参考，绝不能直接作为成交单价**；
  - 货源单件价核验必须由 `source-detail-collector` 进入商品详情页读取真实规格表。

### 2.4 探针 4：1688 详情展开表真实单件价核验（#62 上线门禁）
- **实测样本 1 (`919085178721`)**：
  - 详情页包含完整单维展开规格表（6 项规格，标价 ¥28/¥32/¥34/¥36/¥40/¥45，库存 5000+ PCS，1 PCS 起批）。
  - 核验结果：6/6 项均通过单件价认证（`singlePiecePriceVerified: true`）。
- **实测样本 2 (`981227737111`)**：
  - 规格区标注“1个起批60天老客价”，附带特定消费限制条件。
  - 核验结果：系统准确拦截并记录 `pricing_conditions_unverified`，保持 `singlePiecePriceVerified: false`，防止误判为低价优质货源。

## 4. 风控与异常处理策略

1. **滑块与人机验证 (`captcha_required`)**：
   - 探针已验证 `iframe[src*="captcha"]`、`#nc_1_wrapper` 等特征探测。
   - 触发时保存当前诊断标签页，抛出 `PlatformAccessError`，通知人工在 Chrome 中滑动处理。
2. **访问频繁与限流 (`rate_limited`)**：
   - 复用 `platform-access-guard`，设置最小 2s / 最大 6s 冷却间隔，触发 429 开启熔断保护。
3. **未登录状态 (`login_required`)**：
   - 探测重定向至 `passport.1688.com` 或 `login.taobao.com`，提示用户登录。
4. **死锁回收与会话隔离**：
   - 平台锁采用进程验活（`process.kill(pid, 0)`）与随机 UUID token 释放验证，避免长任务被超时强抢。
