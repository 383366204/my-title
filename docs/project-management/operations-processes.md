# 运营流程补充设计

- **版本**：v1.1
- **日期**：2026-09-15
- **状态**：待团队评审
- **适用范围**：电商全流程运营工具的流程与数据设计
- **本文目标**：把新增运营流程标准化，确保每个流程都有明确输入、输出、人工复核点、任务产物和验收标准

## 0. 新增流程总览

本文补充以下 6 个流程：

| 编号 | 流程 | 定位 | 建议优先级 |
|---|---|---|---|
| OP-04 | 关键词排名与流量监控 | 让标题生成从一次性动作变成持续优化闭环 | P1 |
| OP-06 | 运营异常中心 | 统一收集选品、货源、上架、表单、素材和平台异常 | P0 |
| OP-10 | 单店月度净利润核算 | 按单个店铺和自然月计算经营净利润，并拆解商品贡献与费用结构 | P1 |
| OP-13 | 节令与活动日历 | 提前准备季节品、节日品和平台活动 | P1 |
| OP-15 | 运营 SOP 与检查清单 | 把个人经验沉淀成可执行、可追溯的标准流程 | P1 |
| OP-T | 统一任务中心 | 所有流程的执行入口和跟踪骨架 | P0 |

新增后的运营主线：

```text
机会发现
→ 自动选品
→ 同行分析
→ 货源与好店跟踪
→ 商品贡献预估
→ 标题与素材生成
→ 人工复核
→ 上架
→ 关键词排名 / 流量监控
→ 订单 / 评价 / 售后跟踪
→ 单店月度净利润核算
→ 异常检测
→ 统一任务中心
→ 运营 SOP 执行
→ 活动与节令复盘
→ 反哺下一轮选品
```

## 1. OP-04：关键词排名与流量监控

### 1.1 目标

跟踪商品关键词的排名、展现、点击和转化表现，判断当前标题是否有效，并生成下一步换词或标题优化建议。

> 边界：只做真实数据监控和分析，不做排名操纵、虚假点击或平台规则禁止的行为。

### 1.2 触发方式

| 触发 | 建议频率 |
|---|---|
| 新商品上架后首次 tracking | 上架后 24 小时内 |
| 常规快照 | 每日一次 |
| 标题更新后复盘 | 更新后 3 天、7 天、14 天 |
| 活动期间 | 每日一次，活动结束后输出复盘 |

### 1.3 输入

| 数据 | 来源 | 说明 |
|---|---|---|
| 商品关键词列表 | 标题生成 / 人工复核 | 包含核心词、刚性词、可选词 |
| 搜索排名快照 | 平台数据 / 手动导入 / 授权接口 | 每个关键词的排名和变化 |
| 展现量 | 生意参谋或平台报表 | 判断曝光变化 |
| 点击量 / 点击率 | 生意参谋或平台报表 | 判断关键词和主图吸引力 |
| 成交 / 转化率 | 平台报表 | 判断最终效果 |
| 标题版本 | Workflow run 产物 | 用于归因和回滚 |

### 1.4 流程

```text
采集或导入关键词表现数据
→ 生成每日快照
→ 对比 1 天 / 3 天 / 7 天 / 14 天趋势
→ 结合点击率、转化率、排名变化评分
→ 识别有效词、衰退词、低效词、潜力词
→ 生成标题优化建议
→ 进入统一任务中心
→ 人工确认后触发标题重生成或换词
→ 继续跟踪优化效果
```

### 1.5 输出

#### 关键词健康报告

| 字段 | 说明 |
|---|---|
| keyword | 关键词 |
| currentRank | 当前排名 |
| rankTrend | 排名趋势 |
| impressions | 展现量 |
| ctr | 点击率 |
| cvr | 转化率 |
| score | 综合健康分 |
| state | effective / declining / low-performance / potential |
| reason | 判断理由 |
| suggestedAction | 建议动作 |

#### 标题优化建议

- 保持词：维持当前权重。
- 前置词：把高转化关键词移动到标题更靠前位置。
- 替换词：用蓝海词替换低效词。
- 观察词：数据不足，暂不修改。
- 风险词：合规风险或与商品属性不匹配，建议移除。

### 1.6 生成任务类型

| 任务类型 | 触发条件 |
|---|---|
| keyword_rank_drop | 核心词排名持续下滑 |
| keyword_low_cvr | 展现高但转化低 |
| keyword_low_ctr | 展现高但点击低 |
| title_optimization | 多个关键词表现异常 |
| title_effect_review | 标题更新后需要复盘 |

### 1.7 人工复核点

- 确认数据来源和时间窗口。
- 确认标题修改不会破坏刚性修饰词。
- 确认建议词与真实商品属性一致。
- 确认不使用违禁词或夸大描述。
- 决定是否执行标题更新。

### 1.8 最小数据模型

```json
{
  "keyword": "纯银项链女",
  "entityType": "product",
  "entityId": "product-001",
  "snapshotDate": "2026-09-15",
  "rank": 28,
  "impressions": 1200,
  "clicks": 86,
  "ctr": 0.0717,
  "orders": 5,
  "cvr": 0.0581,
  "titleVersion": "title-v3",
  "trend": {
    "rank7d": -6,
    "impressions7d": 0.12,
    "ctr7d": -0.02
  }
}
```

### 1.9 验收标准

- [ ] 能保存关键词每日快照。
- [ ] 能计算 1 / 3 / 7 / 14 天趋势。
- [ ] 能区分有效词、衰退词、低效词和潜力词。
- [ ] 每个判断都有 reason 和 suggestedAction。
- [ ] 标题建议会进入统一任务中心。
- [ ] 标题更新后能追溯旧版本和新版本效果。
- [ ] 支持手动导入数据，不强制依赖实时接口。

## 2. OP-06：运营异常中心

### 2.1 目标

把分散在各流程里的异常统一收集、去重、分级、派发和跟踪，避免用户在多个节点和报表中来回查找问题。

### 2.2 异常来源

| 来源 | 异常示例 |
|---|---|
| 自动选品 | 关键词数据缺失、商品与刚性词不匹配 |
| 同行分析 | 同行字段缺失、价格异常 |
| 好店跟踪 | 店铺失效、货源涨价、商品缺货 |
| 标题生成 | 违禁词、长度不合规、核心词缺失 |
| 素材处理 | 授权缺失、图片损坏、批处理失败 |
| 运营表单 | 字段缺失、订单状态冲突、导出失败 |
| 关键词监控 | 排名下滑、点击率下降、转化率异常 |
| 平台访问 | 登录失效、滑块、验证码、限流、权限不足 |
| Workflow | 节点超时、重试失败、产物校验失败 |

### 2.3 流程

```text
各流程产生结构化异常事件
→ 异常中心接收
→ 校验字段和实体关联
→ 按实体 + 类型 + 时间窗口去重合并
→ 计算严重程度和影响范围
→ 生成或更新统一任务
→ 推送待处理列表
→ 人工确认或自动执行安全动作
→ 记录处理结果
→ 复盘异常原因
```

### 2.4 异常事件模型

```json
{
  "eventId": "exception-001",
  "type": "stock_out",
  "source": "store-tracking",
  "severity": "high",
  "entityType": "product",
  "entityId": "product-001",
  "workflowRunId": "run-20260915-001",
  "occurredAt": "2026-09-15T08:30:00+08:00",
  "title": "1688 货源缺货",
  "reason": "供应商商品状态为缺货",
  "evidence": {
    "supplierProductId": "1688-001",
    "previousStatus": "available"
  },
  "suggestedAction": "切换备选货源或临时下架",
  "requiresHumanReview": true,
  "status": "open"
}
```

### 2.5 严重程度规则

| 级别 | 定义 | 示例 |
|---|---|---|
| critical | 造成资金、合规、账号或主流程阻塞 | 密钥泄露、平台封禁风险、主流程无法运行 |
| high | 明显影响收入或商品可用性 | 货源缺货、核心商品排名大幅下滑、素材授权缺失 |
| medium | 需要处理但短期影响有限 | 表单字段缺失、非核心词低效 |
| low | 记录和观察即可 | 页面样式提示不完整、低频数据缺失 |

### 2.6 去重与合并规则

同一实体满足以下条件时合并为同一异常：

1. `entityType` 和 `entityId` 相同。
2. `type` 相同。
3. 时间窗口内未关闭。
4. 根因字段基本一致。

合并后保留：

- 首次发生时间。
- 最近发生时间。
- 发生次数。
- 所有来源事件 ID。
- 最高严重程度。
- 最新建议动作。

### 2.7 人工复核点

- 确认异常不是数据误判。
- 确认建议动作是否安全。
- 决定执行、延后或忽略。
- 记录忽略原因，避免同类异常反复打扰。

### 2.8 验收标准

- [ ] 所有新增流程必须能输出结构化异常事件。
- [ ] 异常事件必须关联实体、来源和运行记录。
- [ ] 支持去重、合并和次数统计。
- [ ] 支持按严重程度、来源、实体和状态筛选。
- [ ] 高风险异常必须生成统一任务。
- [ ] 处理结果和忽略原因可追溯。
- [ ] 平台风控类异常只提示人工处理，不自动绕过。

## 3. OP-10：单店月度净利润核算

### 3.1 目标

按“单个店铺 + 单个自然月”的口径计算经营净利润，帮助运营判断这个店铺当月到底赚不赚钱、钱主要花在哪里、哪些商品和费用拖累了净利。

本流程不做企业级财务合并报表，也不跨店汇总。商品级测算只作为月度净利润的归因拆解，不能替代店铺级汇总结果。

### 3.2 核算对象与周期

| 项目 | 定义 |
|---|---|
| storeId | 单个店铺唯一 ID |
| period | 自然月，例如 `2026-09` |
| 口径 | 店铺经营净利润，非法定财务报表净利 |
| 汇总层级 | 先计算店铺月度结果，再拆解商品、渠道和费用 |
| 多店规则 | 每个店铺独立核算，公共费用必须显式配置分摊规则 |

### 3.3 月度收入模型

```text
有效收入
= 商品成交金额
+ 运费收入
+ 平台补贴 / 其他收入
- 退款金额
- 售后减免金额
- 补偿 / 赔付金额
```

如平台报表已经给出净收入，可以导入净收入，但必须记录数据来源和计算口径。

### 3.4 月度成本与费用模型

```text
月度经营净利润
= 有效收入
- 商品采购成本
- 发货物流费
- 包装耗材
- 平台佣金
- 支付 / 手续费
- 推广费用
- 优惠券 / 补贴成本
- 售后与退回运费
- 质量损耗
- 仓储费
- 人力成本
- 房租 / 水电
- 软件与服务订阅
- 平台年费 / 技术服务费
- 其他固定费用
- 税费及附加
```

建议同时输出两个中间指标：

```text
贡献利润 = 有效收入 - 变动成本
经营净利润 = 贡献利润 - 固定费用 - 税费及附加
净利润率 = 经营净利润 / 有效收入
```

### 3.5 输入

| 数据 | 来源 | 说明 |
|---|---|---|
| 店铺 ID | 用户配置 | 核算主体 |
| 月份 | 用户选择 | 默认自然月 |
| 成交订单 | 平台导出 / 授权接口 | 用于收入、退款和商品归因 |
| 退款 / 售后记录 | 平台导出 / 运营表单 | 用于冲减收入和计算损耗 |
| 采购成本 | 1688 订单 / 好店跟踪 / 手动维护 | 可按批次或移动加权 |
| 发货物流费 | 物流账单 / 手动配置 | 按订单或按月汇总 |
| 包装成本 | 用户配置 | 可按订单或商品估算 |
| 平台佣金 / 手续费 | 平台规则 / 账单 | 与成交和退款口径一致 |
| 推广费用 | 推广报表 / 手动导入 | 按店铺月份归集 |
| 优惠券 / 补贴 | 平台报表 / 用户配置 | 与活动周期对齐 |
| 固定费用 | 用户配置 | 人力、房租、软件、仓储等 |
| 税费及附加 | 用户配置 / 会计提供 | 非正式财务申报口径 |
| 分摊规则 | 用户配置 | 多店公共费用分摊，必须显式记录 |

### 3.6 流程

```text
选择店铺和月份
→ 锁定核算周期
→ 导入或读取订单、退款、售后、推广和账单数据
→ 匹配采购、物流、包装、平台费用和固定费用
→ 校验收入、退款、订单数和费用完整性
→ 计算有效收入、变动成本、贡献利润、固定费用
→ 计算经营净利润和净利润率
→ 拆解商品贡献、渠道表现和费用结构
→ 与目标净利润和上月对比
→ 生成调价、停投、清仓、换货源或费用控制任务
→ 人工复核数据缺口和关键假设
→ 归档月度核算结果
```

### 3.7 输出

| 字段 | 说明 |
|---|---|
| storeId | 店铺 ID |
| period | 核算月份 |
| currency | 币种 |
| grossSales | 商品成交金额 |
| refundAmount | 退款金额 |
| effectiveRevenue | 有效收入 |
| variableCost | 变动成本 |
| contributionProfit | 贡献利润 |
| fixedCost | 固定费用 |
| taxAndSurcharge | 税费及附加 |
| netProfit | 经营净利润 |
| netMargin | 净利润率 |
| productBreakdown | 商品级贡献拆解 |
| expenseBreakdown | 费用结构拆解 |
| missingData | 缺失数据和假设项 |
| dataQuality | 数据质量评分 |
| targetComparison | 目标和环比对比 |
| suggestedActions | 建议动作 |
| auditTrail | 数据来源、修改记录和复核人 |

### 3.8 商品级归因规则

商品级结果用于解释店铺净利，不直接等同于店铺净利润：

```text
商品贡献利润
= 商品有效收入
- 商品采购成本
- 分摊物流费
- 分摊包装费
- 分摊平台佣金
- 分摊推广费
- 分摊退款和售后损耗
```

商品级不强行分摊房租、人力、软件等固定费用；如需分摊，必须单独展示分摊规则。

### 3.9 建议规则

| 情况 | 建议 |
|---|---|
| 店铺净利润为负 | 输出亏损主因：收入、贡献利润、退款、推广或固定费用 |
| 贡献利润为正但净利润为负 | 检查固定费用和推广投入是否过高 |
| 单品贡献为负且销量高 | 重新谈判采购价、调整售价或换货源 |
| 推广费占比超过目标 | 复核投放回报和停投任务 |
| 退款率异常 | 触发质量、描述和售后归因任务 |
| 库存积压且贡献低 | 生成清仓或止损方案 |
| 数据缺失率高 | 标记核算结果为低可信度，要求补数据 |

### 3.10 人工复核点

- 确认店铺、月份和币种。
- 确认订单、退款、推广和费用账单是否覆盖完整月份。
- 确认采购成本采用批次成本、移动加权还是估算值。
- 确认固定费用和多店分摊规则。
- 确认税费及附加是否由用户提供，不在系统内做税务申报。
- 确认真实数据、预估值和缺失数据分开标记。
- 确认不会为了提升利润指标做虚假订单或虚假评价。

### 3.11 验收标准

- [ ] 支持选择单店和自然月。
- [ ] 支持导入订单、退款、售后、推广和费用数据。
- [ ] 支持维护变动成本和固定费用字典。
- [ ] 输出有效收入、贡献利润、固定费用和经营净利润。
- [ ] 输出净利润率、目标对比和环比。
- [ ] 支持商品贡献和费用结构拆解。
- [ ] 每个结果都能查看数据来源、假设和缺失项。
- [ ] 关键输入修改后可以重新计算并保留版本。
- [ ] 多店公共费用必须显式配置分摊规则，不得默认合并。
- [ ] 明确标识经营净利润不是正式财务报表净利。
- [ ] 数据不完整时输出低可信度标记，而不是隐藏缺口。

## 4. OP-13：节令与活动日历

### 4.1 目标

根据节日、季节、平台活动和备货周期提前生成运营计划，避免临时选品、临时做素材、临时备货。

### 4.2 日历类型

| 类型 | 示例 |
|---|---|
| 法定节日 | 春节、劳动节、国庆 |
| 传统节日 | 中秋、端午、七夕 |
| 情感节日 | 情人节、母亲节、父亲节 |
| 季节切换 | 春季上新、夏季清仓、秋冬保暖 |
| 平台活动 | 大促、品类活动、预售 |
| 自定义活动 | 店铺周年庆、直播专场 |
| 供应链周期 | 打样、备货、发货、售后高峰 |

### 4.3 流程

```text
维护节令 / 活动日历
→ 配置每个活动的备货周期和素材周期
→ 根据当前日期倒推准备节点
→ 结合灵感选词和市场验证生成候选类目
→ 生成准备任务
→ 进入统一任务中心
→ 人工确认选品和预算
→ 跟踪准备进度
→ 活动结束后复盘
```

### 4.4 活动准备倒推示例

```text
双 11
```

## 6. OP-T：统一任务中心

### 6.1 目标

成为所有运营流程的统一执行入口。任何流程需要人工确认、延期处理、异常响应或后续跟进时，都生成标准化任务，而不是散落在日志、画布节点或本地文件中。

### 6.2 设计原则

1. **单一任务来源**：同一问题只生成一个待处理任务。
2. **实体可追溯**：任务必须关联商品、订单、店铺、素材、关键词或 run。
3. **动作可执行**：任务必须有建议动作和下一步入口。
4. **边界清晰**：需要人工确认的动作不得静默执行。
5. **结果可复盘**：完成、忽略、失败都要留下原因。

### 6.3 任务来源

| 来源 | 任务示例 |
|---|---|
| 自动选品 | 候选品复核、负贡献商品确认 |
| 同行分析 | 竞品降价应对 |
| 好店跟踪 | 换货源、备选店铺确认 |
| 关键词监控 | 标题优化、换词、效果复盘 |
| 单店月度净利润核算 | 调价、停投、清仓和费用控制评估 |
| 活动日历 | 活动选品、素材准备、备货确认 |
| 运营表单 | 订单异常、售后处理、评价回复复核 |
| 素材处理 | 授权确认、失败重试、产物复核 |
| 异常中心 | 所有需要人工处理的异常 |
| SOP | 检查清单执行和复核 |

### 6.4 任务状态流

```text
proposed
→ accepted
→ in_progress
→ blocked
→ resolved
```

可选状态：

```text
dismissed
```

| 状态 | 含义 | 退出条件 |
|---|---|---|
| proposed | 系统生成，等待用户确认 | 接受或忽略 |
| accepted | 用户确认需要处理 | 开始执行 |
| in_progress | 正在处理 | 完成、阻塞或失败 |
| blocked | 等待数据、授权、账号、决策或外部服务 | 阻塞解除或任务取消 |
| resolved | 已完成且结果通过校验 | 归档，可复盘 |
| dismissed | 用户判断不需要处理 | 记录忽略原因并归档 |

### 6.5 任务数据模型

```json
{
  "taskId": "task-001",
  "title": "处理商品 A 货源缺货",
  "description": "1688 供应商商品缺货，需要切换备选货源或临时下架",
  "type": "stock_out",
  "source": "exception-center",
  "sourceEventId": "exception-001",
  "workflowRunId": "run-20260915-001",
  "entityType": "product",
  "entityId": "product-001",
  "severity": "high",
  "priority": "P1",
  "suggestedAction": "switch_supplier_or_pause_listing",
  "actionPayload": {
    "candidateSupplierIds": ["supplier-002"]
  },
  "requiresHumanReview": true,
  "owner": "operator-a",
  "status": "proposed",
  "dueAt": "2026-09-16T12:00:00+08:00",
  "createdAt": "2026-09-15T08:31:00+08:00",
  "updatedAt": "2026-09-15T08:31:00+08:00",
  "resolution": null,
  "auditTrail": []
}
```

### 6.6 必填字段

| 字段 | 说明 |
|---|---|
| taskId | 唯一 ID |
| title | 用户可理解的任务标题 |
| type | 任务类型 |
| source | 来源流程 |
| entityType / entityId | 关联实体 |
| severity | 严重程度 |
| suggestedAction | 建议动作 |
| requiresHumanReview | 是否必须人工确认 |
| status | 当前状态 |
| createdAt / updatedAt | 创建和更新时间 |
| resolution | 处理结果和原因 |

### 6.7 任务优先级规则

| 优先级 | 触发条件 |
|---|---|
| P0 | 合规、安全、账号、主流程阻塞或资金风险 |
| P1 | 缺货、核心商品排名下滑、高利润风险、活动截止临近 |
| P2 | 普通优化、非核心商品修正、数据补录 |
| P3 | 观察类、低影响改进 |

### 6.8 任务去重规则

生成任务前先检查是否存在同类 Open Task：

1. `entityType` 和 `entityId` 相同。
2. `type` 相同。
3. `status` 不是 `resolved` 或 `dismissed`。
4. 未超过重复窗口。

命中时更新已有任务的：

- 发生次数。
- 最新证据。
- 最高严重程度。
- 最新建议动作。
- 最近更新时间。

### 6.9 推荐视图

| 视图 | 用途 |
|---|---|
| 今日待办 | 今天必须处理和即将到期的任务 |
| 高风险任务 | P0 / P1 或 critical / high |
| 按实体查看 | 查看一个商品、店铺、订单或素材的所有任务 |
| 按来源查看 | 判断哪个流程产生最多任务 |
| 阻塞任务 | 等待账号、授权、数据或决策 |
| 已忽略任务 | 复核忽略是否合理 |
| 任务趋势 | 观察异常数量和处理效率 |

### 6.10 核心指标

| 指标 | 用途 |
|---|---|
| 新增任务数 | 判断异常产生速度 |
| 完成率 | 判断处理能力 |
| 超期率 | 判断风险积累 |
| 平均处理时长 | 判断效率 |
| 阻塞时长 | 判断依赖问题 |
| 忽略率 | 判断规则是否过度提醒 |
| 重复任务率 | 判断去重质量 |
| 任务来源分布 | 判断哪个环节最需要优化 |

### 6.11 与 GitHub Project 的边界

- **GitHub Project**：管理开发团队的产品开发 Issue、Bug、迭代和发布。
- **统一任务中心**：管理运营用户在产品内处理的商品、订单、素材、关键词和异常任务。

两者不要混用，但开发任务可以引用产品内任务类型或用户场景。

### 6.12 验收标准

- [ ] 所有新增流程都能生成标准化任务。
- [ ] 任务必须关联来源、实体和证据。
- [ ] 支持接受、开始、阻塞、完成、忽略。
- [ ] 支持去重和合并。
- [ ] 高风险任务不会被自动关闭。
- [ ] 需要人工确认的动作有明确复核点。
- [ ] 处理结果、忽略原因和审计记录可追溯。
- [ ] 提供今日待办和高风险任务视图。

## 7. 首批落地切片

考虑到团队只有 2 人，建议按以下顺序落地，不做大而全系统：

### 第一切片：统一任务中心 MVP

- 定义 Task Schema。
- 支持任务创建、更新、完成、忽略。
- 支持按状态、优先级、来源、实体筛选。
- 接入现有 Workflow 阻塞和失败事件。

### 第二切片：异常中心 MVP

- 定义 Exception Event Schema。
- 将平台访问异常、节点失败、数据校验失败写入异常中心。
- 异常自动生成或更新任务。
- 提供高风险异常列表。

### 第三切片：单店月度净利润 MVP

- 支持选择单店和自然月。
- 导入订单、退款、售后、推广和费用数据。
- 输出有效收入、贡献利润、固定费用、经营净利润和净利润率。
- 标记缺失数据、预估值和数据质量。
- 支持商品贡献和费用结构拆解。

### 第四切片：关键词监控 MVP

- 支持手动导入关键词表现数据。
- 保存每日快照。
- 计算 7 天趋势。
- 生成标题优化任务。

### 第五切片：活动日历 MVP

- 维护活动日期和准备周期。
- 生成倒推计划任务。
- 活动结束生成复盘任务。

### 第六切片：SOP MVP

- 创建 SOP 模板和版本。
- 将 SOP 执行记录关联任务。
- 先落地 3 个高价值 SOP：
  - 新品上架 SOP
  - 缺货处理 SOP
  - 素材授权检查 SOP

## 8. 跨流程数据契约

新增流程必须遵守以下统一约定：

1. 每个实体有稳定 ID：商品、店铺、订单、素材、关键词、run。
2. 每个产物记录来源、版本和生成时间。
3. 每个异常必须能追溯到来源事件。
4. 每个任务必须能追溯到异常、SOP 或流程结果。
5. 每个人工动作必须记录执行人和时间。
6. 所有成本、排名、销量和转化数据必须区分真实值与预估值。
7. 所有平台限制类状态只提示人工处理，不自动绕过。
8. 所有素材处理必须保留授权状态。
