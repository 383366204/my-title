# 项目章程：ecom-ai-tools

- **版本**：v1.3
- **日期**：2026-09-15
- **状态**：待团队确认
- **团队规模**：2 人
- **项目类型**：电商全流程运营自动化工具
- **技术栈**：Node.js、React Web UI、CLI、MCP Server、独立 Skill、外部电商与 AI 能力

## 1. 项目目标

构建一个稳定的电商全流程运营工作台，把运营人员从重复、跨工具、低价值的操作中剥离出来。

项目不是单一选品工具；选品是当前最先落地的运营环节。系统要以可编排的 Workflow 连接多个运营能力，逐步覆盖：

```text
机会发现
→ 自动选品
→ 同行分析
→ 货源与好店跟踪
→ 商品贡献预估
→ 标题与商品上架
→ 铺货复核
→ 关键词排名与流量监控
→ 订单执行表
→ 评价跟踪表
→ 素材批量处理
→ 单店月度净利润核算
→ 运营异常识别
→ 统一任务处理
→ 节令与活动复盘
→ 运营 SOP 沉淀
```

核心产品形态：

1. **Workflow 工作台**：用户在一个画布中配置、运行、暂停、重试和复核流程。
2. **领域 Skill**：选品、同行分析、标题生成、单店月度净利润核算、表单生成、素材处理等能力可独立复用。
3. **统一任务中心**：所有流程的人工确认、异常响应和后续跟进都生成标准化任务。
4. **多入口一致性**：CLI、MCP Server、Web UI 复用同一套核心实现。
5. **人机协同**：机器做收集、清洗、计算、生成和批处理；人做判断、授权操作和最终复核。
6. **可追溯运行**：每次运行留下输入、阶段状态、产物、异常、任务、人工动作和处理结果。

## 2. 业务价值

| 价值 | 衡量方式 |
|---|---|
| 减少市场调研和选品时间 | 从机会发现到候选货源的端到端操作时间 |
| 提升同行分析效率 | 同行商品、价格、标题、销量等信息的结构化完整度 |
| 提升商品上架质量 | 标题合规率、刚性词命中、铺货复核通过率 |
| 提升关键词优化效率 | 关键词快照完整率、标题优化建议采纳率、优化后效果变化 |
| 提升单店盈利判断能力 | 月度净利润核算覆盖率、净利润率准确性、费用归因完整率、月结耗时 |
| 降低表单制作成本 | 订单执行表、评价跟踪表的生成时间和错误率 |
| 降低素材处理成本 | 授权素材批处理耗时、人工修图次数 |
| 降低异常处理成本 | 异常去重率、任务完成率、平均处理时长、超期率 |
| 提升活动准备能力 | 活动任务提前完成率、临时缺货率、活动目标达成率 |
| 降低重复操作 | 每日 Workflow 完成率、人工干预次数、复跑成功率 |
| 提高可诊断性 | 外部依赖失败后的定位时间和恢复时间 |

## 3. 成功标准

项目成功的最低标准：

1. 选品闭环“灵感选词 → 人工筛词 → 市场验证 → 货源选品 → 单店月度净利润核算 → 标题生成 → 铺货复核”稳定运行并留下可追溯产物。
2. 同行分析结果能结构化输出，并与选品决策建立关联。
3. 关键词排名、展现、点击和转化数据能形成快照、趋势和标题优化建议。
4. 运营异常能统一进入异常中心，并生成或更新去重后的任务。
5. 统一任务中心能跟踪接受、执行、阻塞、完成、忽略和审计记录。
6. 单店月度净利润核算能按店铺和自然月展示有效收入、变动成本、贡献利润、固定费用、经营净利润、净利润率和数据质量。
7. 节令与活动日历能按准备周期倒推任务并生成复盘。
8. 运营 SOP 和检查清单有版本、执行记录和复核结果。
9. 运营表单能从 Workflow 产物生成，字段来源清晰，支持复核和修正。
10. 授权素材可以批量处理，处理结果可追踪，未授权素材会被拒绝或标记。
11. 外部平台登录、验证码、滑块、限流等状态能被结构化识别，并明确交给人工处理。
12. `npm test` 保持通过，完整回归按 `npm run test:all` 执行。
13. 关键决策、风险和任务状态可追溯。
14. 不提供虚假交易、操纵评价、绕过平台风控等违反平台规则或法律法规的能力。

## 4. 产品范围

### 4.1 范围内

#### 运营 Workflow 与运行时

- 运营流程模板、节点编排、参数校验。
- 运行、暂停、继续、取消、重试和恢复。
- SSE 日志、进度、阶段产物和运行历史。
- 阻塞状态、人工动作提示和复核记录。

#### 机会发现与自动选品

- 新闻、日历、字典和趋势来源的灵感词根发现。
- 关键词候选生成、去重、排序和人工筛词。
- 生意参谋等市场数据验证。
- 1688 商品搜索、评分、过滤、定价建议和风险提示。
- 选品理由和淘汰理由可解释。

#### 同行与市场分析

- 淘宝 / 1688 同行商品信息提取。
- 标题、价格、销量、属性和卖点对比。
- 同行策略摘要与选品决策关联。

#### 货源与好店跟踪

- 1688 商品与店铺信息结构化。
- 好店候选池、跟踪维度和更新记录。
- 价格、销量、商品变化提示。
- 跟踪结果与选品、铺货复核、换货源任务打通。

#### 关键词排名与流量监控

- 关键词排名、展现、点击、成交和转化快照。
- 1 / 3 / 7 / 14 天趋势对比。
- 有效词、衰退词、低效词、潜力词识别。
- 标题优化建议和标题版本效果复盘。
- 支持授权接口或手动报表导入。

> 本项目只做真实数据分析和标题优化建议，不做排名操纵、虚假点击或平台规则禁止的行为。

#### 单店月度净利润核算

- 按“单个店铺 + 单个自然月”核算经营净利润。
- 汇总商品成交、退款、售后、推广、采购、物流、包装、平台费用和固定费用。
- 输出有效收入、变动成本、贡献利润、固定费用、经营净利润、净利润率和数据质量。
- 支持商品贡献、渠道表现和费用结构拆解。
- 支持多店公共费用显式分摊规则。
- 核算数据来源、假设和缺失项可查看、可修改、可追溯。

> 单店月度净利润是运营经营分析口径，不等同于法定财务报表净利或财务结算系统。

#### 节令与活动日历

- 法定节日、传统节日、季节切换、平台活动和自定义活动。
- 备货周期、素材周期、投放周期倒推。
- 活动候选类目、准备任务和截止时间。
- 活动后目标、异常、库存和利润复盘。

#### 统一任务中心与异常中心

- 商品、订单、店铺、素材、关键词、run 等实体的统一任务模型。
- 异常事件收集、去重、合并、分级和溯源。
- 任务状态：proposed、accepted、in_progress、blocked、resolved、dismissed。
- 今日待办、高风险任务、阻塞任务和任务趋势视图。
- 人工确认、处理结果、忽略原因和审计记录。

#### 商品上架与标题生成

- 多模型 LLM 的核心词提取和标题生成。
- 刚性 / 可选修饰词管理。
- 三段式 SEO 标题、长度控制和违禁词过滤。
- 批量生成、失败隔离和标题版本追踪。

#### 运营表单

- 订单执行表：跟踪真实订单的执行、发货、售后和复盘状态。
- 评价跟踪表：跟踪真实用户评价、回复建议、售后处理和改进项。
- 表单字段从 Workflow 产物自动填充，并保留人工复核与修正记录。

> 项目不提供“刷单”能力。若业务口语中的“刷单表”指真实订单执行跟踪，应统一命名为“订单执行表”；虚假交易、操纵销量和篡改评价均不在范围内。

#### 素材批量处理

- 用户拥有合法处理权的商品图、素材图批量处理。
- 批量水印处理、格式转换、压缩、命名和归档。
- 素材来源、授权状态和处理记录可追踪。
- 未授权或来源不明素材必须被拒绝或标记为待确认。

#### 运营 SOP 与检查清单

- 新品上架、缺货处理、换供应商、清仓、差评处理、活动准备等 SOP。
- SOP 触发条件、检查项、输出产物和异常处理预案。
- SOP 版本管理和执行记录。
- 检查结果与统一任务、异常和 run 记录关联。

#### 平台适配与诊断

- 1688、淘宝、生意参谋等平台能力封装。
- 登录、验证码、滑块、权限、限流、超时状态结构化。
- 环境变量、API Key、浏览器调试和账号状态诊断。

### 4.2 范围外

- 不自动输入密码、验证码，不自动拖动滑块。
- 不绕过外部平台风控、权限或访问限制。
- 不提供虚假交易、刷单、操纵销量、刷评价或篡改排名的能力。
- 不做排名操纵、虚假点击或虚假流量。
- 不处理无合法处理权的第三方水印或版权素材。
- 不建设通用 ERP、WMS、客服系统或财务系统；必要时只做导入导出和集成。
- 不把单店月度净利润结果作为正式财务报表、税务申报或结算依据。
- 不引入 TypeScript、CI/CD、ESLint 等当前范围外的基础设施改造，除非单独立项。
- 不做复杂的组织级资源与成本管理。
- 不维护与运营主流程无关的通用 UI 组件库。

## 8. 约束与假设

### 约束

- 团队只有 2 人，必须限制并行任务数量。
- 依赖 LLM、1688、生意参谋、淘宝等外部服务，可用性不可完全控制。
- 关键词和流量数据可能需要手动导入或授权接口。
- 浏览器自动化和平台风控状态需要人工参与。
- 平台规则和素材授权边界优先于自动化效率。
- 当前代码库以 JavaScript / CommonJS 为主，Web UI 为 React。

### 假设

- 团队成员都能访问 GitHub 仓库和 Project。
- 外部 API Key 由团队成员安全配置在本地 `.env`，不提交到仓库。
- 用户接受必要时进行人工登录、验证码或滑块处理。
- 用户只处理自己拥有合法权利的素材。
- 用户能提供必要的采购、物流、包装、平台费率、推广、退款、售后、固定费用和税费假设。
- 项目以持续迭代交付，而不是一次性固定范围交付。

## 9. 治理与变更控制

| 变更类型 | 处理方式 |
|---|---|
| 普通任务调整 | 在 Backlog / Issue 中更新，不需要正式审批 |
| 新增运营环节 | 先明确上下游、数据产物、异常类型、任务类型、人工复核点和合规边界 |
| 里程碑延期 | 周会评估影响，更新 Backlog 和风险登记册 |
| 范围新增 | 先判断是否属于范围外；若纳入，必须写清价值、验收和放弃项 |
| 架构调整 | 记录 ADR，说明背景、方案、后果和回滚策略 |
| 外部依赖或平台规则变更 | 更新风险登记册和诊断方案 |
